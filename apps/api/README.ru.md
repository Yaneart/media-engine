# Media Engine API

[English](README.md) | **Русский**

Это готовый HTTP API для Media Engine. Он нужен, когда с движком должен работать браузер, мобильное
приложение, бот или другой сервис.

API находится внутри этого репозитория и отдельно в npm не публикуется.

## Локальный запуск

Выполните из корня проекта:

```bash
pnpm install
cp .env.example .env
pnpm dev:api
```

API запустится на <http://127.0.0.1:3000>. Swagger будет доступен на
<http://127.0.0.1:3000/docs>.

Проверить поиск можно так:

```bash
curl 'http://127.0.0.1:3000/media/search?title=Интерстеллар&language=ru'
```

## Основные маршруты

- `GET /media/search` — поиск фильма, сериала или аниме;
- `GET /media/details` — подробная информация по внешнему ID;
- `GET /media/availability` — варианты плееров и потоков;
- `GET /media/torrents` — поиск раздач, если включены torrent-провайдеры;
- `GET /providers` — список активных провайдеров;
- `GET /health`, `/health/live` и `/health/ready` — состояние сервиса;
- `GET /docs` — полное интерактивное описание API.

Для подробностей передавайте ID вместе с его типом: например, `imdb=tt0816692` или
`ids.shikimori=20`. Обычный `id` непонятен без источника, поэтому API его не принимает.

## Настройка

Локальные настройки лежат в корневом файле `.env`. Скопируйте `.env.example`: там уже есть
нормальные значения для разработки — порт, CORS, таймауты и лимиты запросов.

Для метаданных и плееров ваши API-ключи не нужны. Поиск torrent-раздач по умолчанию выключен. Чтобы
его включить, укажите нужные провайдеры, например:

```dotenv
MEDIA_ENGINE_TORRENT_PROVIDERS=yts-torrent,jacred-torrent
```

Для маршрутов воспроизведения исходного файла нужен приватный серверный токен. Создайте его командой
`openssl rand -hex 32` и вставьте в `.env`:

```dotenv
MEDIA_ENGINE_ORIGINAL_TORRENT_TOKEN=сюда_вставьте_полученное_значение
```

Не добавляйте этот токен в браузерный код и не называйте переменную с префиксом `VITE_`. В примере
токен остаётся на сервере, а браузер обращается к защищённым маршрутам через небольшой BFF.

## Как устроено torrent-воспроизведение

В полный Docker Compose входит TorrServer. Media Engine выдаёт браузеру временную ссылку только на
один выбранный файл. Приватный токен и внутренний адрес TorrServer в браузер не попадают.

API передаёт исходные байты без конвертации и перекодирования. Поэтому файл воспроизведётся только
в том случае, если браузер поддерживает его контейнер и кодеки. Полная схема безопасности и
жизненного цикла описана в
[архитектурном решении](../../docs/decisions/0001-original-torrent-streaming.md).

## Проверки

```bash
pnpm --filter @media-engine/api typecheck
pnpm --filter @media-engine/api test
pnpm --filter @media-engine/api test:e2e
```

Публичные источники иногда отвечают медленно или временно не работают. API умеет вернуть данные от
исправных источников и отдельно показать сбой. Поэтому состояние `degraded` у readiness-проверки
по-прежнему возвращается с HTTP 200.
